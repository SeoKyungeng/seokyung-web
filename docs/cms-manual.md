## 1. 시작하기 전에

### 이 매뉴얼의 목적

홈페이지 콘텐츠를 다음과 같은 상황에서 **직접** 수정하실 수 있게 돕습니다.

- 설비 신규 도입 → 설비 목록에 추가
- 제품 사진 새로 찍음 → 갤러리 교체
- 회사 주소 · 전화번호 변경 → 푸터/Contact 페이지 업데이트
- 대표이사 인사말 문구 교체

### 필요한 것

1. **회사 GitHub 계정** — Sanity Studio 로그인은 **회사 GitHub 계정 연동**으로 이루어집니다. 아직 초대받지 못했다면 개발 담당자에게 요청하세요.
2. **PC 브라우저** (Chrome, Edge, Safari 권장) — 모바일도 가능하지만 PC가 편합니다.
3. **인터넷 연결**

> ⚠️ 개인 GitHub 계정이 아닌 **업무용 회사 GitHub 계정**을 사용해야 합니다. 개인 계정으로 로그인하면 권한이 부여되지 않습니다.

## 2. Studio 접속하기

### 접속 주소

```
https://www.seokyungeng.com/studio
```

### 첫 접속 순서

1. 위 주소를 브라우저 주소창에 입력합니다.
2. **"Continue with GitHub"** 버튼을 클릭합니다.
3. 회사 GitHub 계정으로 로그인합니다. (이미 브라우저에 로그인되어 있다면 자동)
4. Sanity 접근 권한 승인(Authorize) → Studio 화면이 열립니다.

![이미지 placeholder: Studio 로그인 화면](./images/cms-manual/01-login.png)

### 두 번째 이후 접속

이미 로그인한 상태라면 URL만 입력하면 바로 Studio가 열립니다. 로그아웃되었다면 GitHub 로그인 한 번 더.

> 💡 북마크/즐겨찾기에 등록해두시면 편합니다.

## 3. 화면 한눈에 보기

Studio는 크게 **왼쪽 메뉴 · 가운데 문서 목록 · 오른쪽 편집 영역** 세 구역으로 나뉩니다.

![이미지 placeholder: Studio 전체 화면](./images/cms-manual/02-overview.png)

### 왼쪽 메뉴 구조

| 구분 | 메뉴 이름 | 설명 |
| --- | --- | --- |
| **싱글턴** (고정 문서) | 회사 정보 | 주소·전화·팩스·이메일·좌표 |
| | 대표이사 인사말 | CEO 이름·직함·인사말 |
| | 경영 철학 | 슬로건 + 핵심 가치 3가지 |
| | 조직도 | 부서 트리 구조 |
| | 지속가능경영 (ESG) | 인트로 + E/S/G 3섹션 |
| | 통계 지표 | 홈페이지 핵심 수치 |
| --- (구분선) --- | | |
| **컬렉션** (여러 건) | 설비 | 보유 설비 목록 |
| | 가공 제품 | 제품 갤러리 이미지들 |
| | 고객사 | 파트너사 로고 |

- **싱글턴**은 "하나만 존재하는 문서"입니다. 새로 추가할 수 없고 편집만 가능합니다.
- **컬렉션**은 "여러 건을 계속 쌓는" 문서입니다. 새로 추가하거나 삭제할 수 있습니다.

### 상단 내비게이션

화면 최상단에는 `Content`, `Vision` 같은 탭이 있습니다.

- **Content** ← 여러분이 사용하는 탭입니다.
- **Vision** — 개발자용 쿼리 도구입니다. **건드리지 마세요.**

### 편집 영역의 핵심 버튼

문서를 편집할 때 화면 하단 또는 우측에 다음 버튼이 보입니다.

- **Publish** (게시) — 변경사항을 실제 웹사이트에 반영합니다.
- **···** (더보기) — "Discard changes (변경 취소)", "History (이력 보기)" 등.
- **초안 저장** — 별도 버튼 없이 **입력하면 자동 저장**됩니다. (하지만 웹사이트에는 반영 안 됨 → 6장 참조)

## 4. 한국어 · 영문 입력 규칙 (중요)

홈페이지는 **한국어(`/ko`)와 영문(`/en`) 두 가지 언어**를 지원합니다. 그래서 거의 모든 텍스트 필드는 **한국어와 영문을 둘 다** 입력해야 합니다.

![이미지 placeholder: 한국어/English 입력 필드](./images/cms-manual/03-localized-field.png)

### 두 가지 다국어 타입

| 타입 | 용도 | 예시 |
| --- | --- | --- |
| **다국어 문자열** (`localizedString`) | 한 줄 짧은 텍스트 | 설비명, 고객사명, 주소 |
| **다국어 본문** (`localizedText`) | 여러 줄 긴 텍스트 (줄바꿈 유지) | 인사말 본문, ESG 설명 |

### 반드시 지켜주세요

- 🚨 **한국어만 입력하고 영문을 비워두면 "Publish"가 실패합니다.**
- 영문을 쓰기 어려운 경우:
  1. 가능하면 간단한 영문을 직접 작성 (구글 번역 참고)
  2. 영문 번역이 어려우면 **저장만 하고 Publish는 미루고** 담당 개발자/매니저에게 번역 요청 메모 남기기
  3. ❌ 한글을 그대로 영문 필드에 복사하지 마세요 (해외 사용자에게 그대로 노출됨)

## 5. 자주 하는 작업 시나리오

### 5.1 설비 추가하기

> 신규 설비가 입고되어 목록에 추가해야 할 때 사용합니다.

**단계:**

1. 왼쪽 메뉴 **"설비"** 클릭.
2. 우측 상단 **"+" 버튼** → "New 설비 (Equipment)" 클릭.
3. 아래 필드를 입력합니다.

| 필드 | 입력 방법 | 예시 |
| --- | --- | --- |
| **식별 ID** | `eq-01`, `eq-02`처럼 **기존 번호 다음 이어지는 번호**로 입력. 영문 소문자·숫자·하이픈만 가능. | `eq-16` |
| **카테고리** | CNC / MCT (머시닝센터) / 선반 (Lathe) / 기타 중 선택 | MCT |
| **설비명** | 한국어·English 둘 다 입력 | 한국어: `5축 머시닝센터` / English: `5-Axis Machining Center` |
| **모델명** | 영문/숫자 (번역 없이 공통) — 없으면 비워두기 | `VM-5X` |
| **제조사** | 한국어·English 둘 다 입력 | 한국어: `두산공작기계` / English: `Doosan Machine Tools` |
| **보유 수량** | 숫자 (1 이상) | `2` |
| **사진** | 드래그&드롭 또는 "Upload" 클릭 → JPG/PNG | (파일 선택) |
| **스펙 목록** | "Add item" 버튼으로 추가. 항목명(한영) + 값(공통) | 항목명: `이송 속도`/`Feed Rate`, 값: `10,000mm/min` |
| **정렬 순서** | 작은 숫자가 먼저 표시. 기존 마지막 값 + 1 권장 | `16` |

4. 모든 빨간 별표(`*`) 필수 필드가 채워졌는지 확인.
5. 하단 **"Publish"** 버튼 클릭 → 끝.

![이미지 placeholder: 설비 추가 화면](./images/cms-manual/04-equipment-new.png)

**사진 자르기 (hotspot):** 사진을 업로드한 뒤 이미지 위로 마우스를 올리면 "Edit hotspot" 버튼이 보입니다. 중요한 부분(ex. 기계 본체 중앙)을 원으로 지정하면 작은 썸네일에서도 그 부분이 잘 보이게 자동 자릅니다. 필수는 아닙니다.

### 5.2 설비 사진 교체하기

1. 왼쪽 메뉴 **"설비"** → 교체할 설비 선택.
2. **"사진"** 필드에서 기존 이미지 위의 **"×" 삭제 아이콘** 클릭.
3. 새 이미지 드래그&드롭.
4. **Publish** 클릭.

> 💡 기존 이미지를 안 지우고 바로 드래그해도 교체됩니다.

---

### 5.3 제품 이미지 추가 · 교체하기

> 가공 제품 갤러리(`/products` 페이지)의 이미지 관리.

**새 이미지 추가:**

1. 왼쪽 메뉴 **"가공 제품"** → 우측 상단 **"+"** → 새 문서.
2. 입력:
   - **식별 ID**: `pr-01`, `pr-02` 형식
   - **카테고리**: 방산 / 열교환기 / 산업용 중 선택 (선택사항)
   - **이미지**: 업로드 (필수)
   - **대체 텍스트 (접근성)**: 한국어·English 둘 다
     - 예: 한국어 `방산 부품 가공 사례`, English `Defense parts machining example`
     - → **왜 필요한가요?** 시각장애인 스크린리더가 읽고, 이미지 로딩 실패 시에도 표시됩니다. 구글 검색에도 도움됩니다.
   - **정렬 순서**: 갤러리 노출 순서

3. **Publish**.

**기존 이미지 교체:**

설비 사진 교체와 동일합니다 (5.2 참조).

![이미지 placeholder: 제품 편집 화면](./images/cms-manual/05-product-edit.png)

### 5.4 고객사 로고 추가하기

1. 왼쪽 메뉴 **"고객사"** → **"+"** → 새 문서.
2. 입력:
   - **식별 ID**: `cl-01` 형식
   - **고객사명**: 한국어·English (예: `한화에어로스페이스` / `Hanwha Aerospace`)
   - **로고**: 이미지 업로드 (PNG 투명 배경 권장)
   - **정렬 순서**: 노출 순서
3. **Publish**.

> 💡 로고가 없어도 저장은 가능합니다. 텍스트만으로 표시됩니다.

### 5.5 회사 정보 변경하기

> 푸터와 Contact 페이지에 표시되는 주소·연락처 정보를 일괄 수정합니다.

1. 왼쪽 메뉴 **"회사 정보"** 클릭. (이미 존재하는 단일 문서가 열립니다 — 새로 만들 필요 없음)
2. 수정할 필드:

| 필드 | 설명 |
| --- | --- |
| **회사명** | 한국어·English |
| **주소** | 한국어·English (도로명 주소 권장) |
| **전화** | 하이픈 포함 (`02-1234-5678`) |
| **팩스** | 하이픈 포함 |
| **이메일** | 유효한 이메일 형식 |
| **지도 좌표 (위도·경도)** | ⚠️ **개발자 문의 권장** — 잘못 입력하면 지도가 엉뚱한 곳을 가리킵니다 |

3. **Publish** 클릭.

### 5.6 대표이사 인사말 수정하기

1. 왼쪽 메뉴 **"대표이사 인사말"** 클릭.
2. 수정할 필드:
   - **대표 이름** (한국어·English)
   - **직함** (예: 한국어 `대표이사` / English `CEO`)
   - **인사말 > 강조 문구** — 한 줄 핵심 메시지 (About 페이지 중앙 큰 글씨)
   - **인사말 > 본문** — 여러 단락. **줄바꿈은 Enter 두 번** (빈 줄로 단락 구분)
3. **Publish**.

### 5.7 ESG 섹션 문구 수정하기

> `/sustainability` 페이지 전체 문구 관리.

1. 왼쪽 메뉴 **"지속가능경영 (ESG)"** 클릭.
2. 구조:
   - **인트로** (비전 / 설명)
   - **Environment (환경)** — E 섹션
   - **Social (사회)** — S 섹션
   - **Governance (지배구조)** — G 섹션
3. 각 E/S/G 섹션의 필드:
   - 제목, 서브 타이틀, 설명 (모두 한영)
   - 아이콘 이름 — ⚠️ **변경하지 마세요** (lucide-react 아이콘 이름. 잘못 쓰면 아이콘이 안 보입니다. 변경 시 개발자 문의)
   - 대표 이미지 (선택)
   - 세부 항목 — "Add item"으로 체크리스트 추가
4. **Publish**.

![이미지 placeholder: ESG 편집 화면](./images/cms-manual/07-esg.png)

### 5.8 통계 지표 수정하기

> 홈 페이지 상단의 "핵심 수치" 섹션 (예: 설비 25대, 경력 30년).

1. 왼쪽 메뉴 **"통계 지표"** 클릭.
2. **지표 목록** 배열에서 수정할 항목을 펼침.
3. 각 항목:
   - **라벨** — 한영 (예: `보유 설비` / `Equipment`)
   - **수치** — 숫자 카운트업용 (예: `25`)
   - **텍스트 (대체)** — 숫자가 아니라 **문자**로 표시할 때만 사용 (예: `턴키 가공 전문`). **"수치"와 "텍스트" 중 하나만 입력**합니다.
   - **접두사** / **접미사** — 숫자 앞뒤에 붙는 단위 (예: 접미사 `대`, `년`, `+`)
4. **Publish**.

## 6. 초안 저장 vs 발행(Publish)

Sanity는 **초안(Draft)** 과 **게시본(Published)** 을 분리해서 관리합니다.

| 상태 | 설명 | 웹사이트 반영 |
| --- | --- | --- |
| **초안 (Draft)** | 입력한 내용이 자동 저장됩니다. 다른 사람에게는 안 보입니다. | ❌ 안 됨 |
| **게시본 (Published)** | Publish 버튼을 눌러 확정한 상태. | ✅ 즉시 반영 |

### 실수했을 때

- **변경 취소 (Discard changes)**: 편집 화면 우측 "···" 메뉴 → "Discard changes". 초안을 버리고 마지막 게시본으로 되돌립니다.
- **이전 버전 복원 (History)**: 우측 상단 **시계 아이콘(History)** 클릭 → 과거 버전 목록 → 원하는 시점 선택 → "Restore".

![이미지 placeholder: History 화면](./images/cms-manual/08-history.png)

## 7. 반영 시간

**Publish를 누르면 약 1~30초 내에 실제 웹사이트에 자동 반영됩니다.**

원리: Sanity가 변경을 감지해 서버로 "갱신 요청"을 보내고, 서버가 캐시를 새로 고칩니다.

### 반영이 안 될 때

1. **30초 정도 기다려보세요** — 간혹 시간이 걸립니다.
2. 브라우저에서 **Ctrl + Shift + R** (Mac: Cmd + Shift + R) — 강력 새로고침.
3. 그래도 안 되면 **10분 후 재확인**.
4. 10분 이상 반영 안 되면 → **10번 문의처**로 연락.

## 8. 자주 하는 실수 FAQ

### Q1. Publish 버튼을 눌렀는데 빨간 오류 메시지가 떠요.

👉 **필수 입력 필드가 비어있거나, 한국어만 입력하고 영문을 비웠을 확률이 높습니다.** 오류 메시지에 빨간색으로 표시된 필드를 확인하세요. 모든 `localizedString`/`localizedText` 필드는 한영 둘 다 필수입니다.

### Q2. 이미지 · 글자를 수정했는데 실제 홈페이지에 안 보여요.

👉 **Publish 버튼을 눌렀는지** 확인. 초안 저장만 되어 있으면 반영되지 않습니다. (편집 화면 하단에 "Publish" 버튼이 파란색/활성화 상태라면 아직 미발행입니다.)

### Q3. 회사 정보 같은 문서가 삭제가 안 돼요.

👉 **정상입니다.** "회사 정보", "대표이사 인사말" 같은 **싱글턴 문서**는 실수로 삭제되지 않도록 잠겨 있습니다. 내용을 비우고 싶으면 각 필드의 텍스트를 직접 지운 뒤 Publish.

### Q4. 실수로 내용을 잘못 수정했어요.

👉 우측 상단 **History(시계 아이콘)** → 이전 버전 선택 → "Restore". 마지막 Publish 이전 상태로 되돌릴 수 있습니다.

### Q5. 설비/제품 순서를 바꾸고 싶어요.

👉 각 항목의 **"정렬 순서"** 숫자를 변경하세요. 작은 숫자가 먼저 표시됩니다.

### Q6. 모바일(스마트폰)에서도 편집 가능한가요?

👉 가능하지만 **PC 권장**합니다. 이미지 업로드, 긴 텍스트 입력이 불편합니다.

### Q7. 한 번에 여러 필드를 수정하고 싶어요.

👉 모두 수정한 뒤 **한 번만 Publish**하세요. 필드마다 따로 저장할 필요 없습니다.

### Q8. 영문 번역이 정말 어려운데 어떻게 할까요?

👉 ① 구글 번역/DeepL 초벌 번역 → ② Publish하지 말고 초안 상태로 두기 → ③ 담당 매니저에게 "영문 번역 리뷰 요청" 메모 공유.

### Q9. 실수로 문서 전체를 삭제했어요.

👉 **컬렉션**(설비/제품/고객사) 문서는 삭제되지만 **30일 이내라면 복구 요청 가능**합니다. 즉시 개발자 문의.

## 9. 보안 · 계정 관리

- **공용 PC에서 로그인하지 마세요.** 반드시 개인 업무 PC에서만.
- **이상한 화면**(빈 화면, 오류 반복)이 나오면 → 우측 상단 사용자 아이콘 → Sign out → 재로그인.
- **GitHub 계정 접근 권한을 분실/변경**한 경우 → 개발자에게 **재초대 요청**.
- **새 담당자 추가** → 개발자에게 해당 인원의 **회사 GitHub 아이디**를 전달하면 Sanity 프로젝트에 멤버로 추가합니다.
- **회사 GitHub 조직 탈퇴 시** → Sanity 접근도 자동으로 해제되므로, 인수인계 전에 개발자에게 알려주세요.
